## 📌 Обзор Проекта
**StoryTracker** — это высоконагруженный бэкенд-сервис на **C# .NET 10.0 (ASP.NET Core Web API)** для автоматизации генерации игровых миров и сущностей в настольных ролевых играх (D&D 5e) с поддержкой экспорта в экосистему **Foundry VTT**.

Проект объединяет интеграцию с LLM (Google Gemini API), локальную обработку больших компендиумов данных (дампы 10 МБ JSON) и строго типизированный REST API.

---

## 🏛️ Архитектурные Паттерны и Проектирование (Software Architecture)

### 1. Архитектура Слоев и SOLID
- **Разделение ответственности (SRP):**
  - `AiService` / `IAiService` — отдельный сервисный слой (AI Gateway) для взаимодействия с Gemini API через Typed HttpClient.
  - `NpcEnrichmentService` — сервисный слой для обогащения сущностей (автоматическая выгрузка аватаров и случайный подбор предметов из дампа).
  - `NpcService`, `FactionService`, `ItemService` — бизнес-логика предметных областей.
  - `NpcController`, `FactionController`, `ItemController` — контроллеры входных данных.
- **Инверсия зависимостей (DIP):** Все связи между контроллерами и сервисами построены строго через интерфейсы (`IAiService`, `INpcService`, `INpcEnrichmentService`, `IFactionService`), зарегистрированные в IoC-контейнере ASP.NET Core.

### 2. Паттерн Результата (Result Pattern vs Exceptions)
- В проекте **полностью исключено выброс исключений (exceptions) для контролируемых ошибок**.
- Внедрен пользовательский дженерик-класс `Result<TValue>` с защищенным от вызова провалившегося значения `.Value`.
- Созданы доменные рекорды `Error` и структурированный каталог ошибок `DomainErrors` (`DomainErrors.Gpt.*`, `DomainErrors.Item.*`, `DomainErrors.Faction.*`).

### 3. Составные Сущности (Composition over Inheritance)
- Использование композиции при проектировании сложных доменных объектов:
  - Модель `FactionStat` включает в себя вложенный объект лидера (`FactionLeader`) и вложенный объект штаб-квартиры (`Headquarters`).
  - Составная генерация 3-в-1 за один сетевой запрос к Gemini API.

## 🤖 Интеграция с LLM и Генерация JSON-Схем

### 1. Строгая Типизация ответов ИИ (Structured Outputs)
- Использование рекурсивного построения схем `ResponseSchema` и `SchemaProperty` для удержания нейросети в рамках 100% валидного JSON без галлюцинаций.
- Выделен модуль `AiSchemaBuilder`, генерирующий многоуровневые JSON-схемы (включая массивы `ARRAY` и вложенные объекты `OBJECT`).

### 2. Промпт-Инжиниринг и Ограничения
- Использование `StringBuilder` в `GeneratePromts` с системными инструкциями для Gemini 3.1 Flash Lite.
- Динамический расчет бюджетов характеристик, генерация тегов редкости (`common`, `uncommon`, `rare`, `legendary`) и сопоставление их со статами персонажей.

---

## 💾 Работа с Данными и Экспорт в Foundry VTT

### 1. Обработка локальных компендиумов (Local Dump Indexing)
- Загрузка и потоковый парсинг локального дампа предметов на 10 МБ (`dump_v13_raw.json`) в `ItemDataStorage`.
- Фильтрация пулов лута по классам персонажей (`_classLootPools`) и типам предметов.
- Безопасное глубокое клонирование узлов JSON (`DeepClone()`) при наполнении инвентаря персонажа.

### 2. Двухрежимный экспорт (Environment-Aware Streaming)
- **Development Mode:** Автоматическое сохранение скомпилированного шаблона FVTT в локальную папку `Export/` на диске и возврат сырого C# DTO для отладки в Scalar UI.
- **Production Mode (Azure):** Конвертация JSON-строки в UTF-8 байтовый поток и прямое скачивание через HTTP `FileResult` с проставлением заголовков `Content-Disposition: attachment; filename="..."` без сохранения на диск сервера.

## 🔒 Инфраструктура, Безопасность и DevOps

- **Управление секретами:** Использование `DotNetEnv` для локального чтения `.env`, вынос чувствительных API-ключей Gemini из репозитория, настройка правил `.gitignore` и успешно пройденная валидация **GitHub Push Protection**.
- **CI/CD:** Настроен автоматический деплой через **GitHub Actions** (`master_storytracker.yml`) в облако **Azure App Service**.
- **Документирование API:** Настроена интеграция **Scalar OpenAPI** для интерактивного тестирования REST API в режиме разработки.
- **Git Flow:** Ведение разработки в короткоживущих фича-ветках (`feature/*`, `refactor/*`), выполнение атомарных коммитов, использование Pull Request и разрешения конфликтов мерджа.
